## 2. Delivered Artifacts

- `scripts/inventory_d3s.py` recursively discovers supported videos, excludes
  `_downloads` cache copies, reads technical metadata with
  `cv2.VideoCapture`, releases the capture in a `finally` block, and writes a
  deterministic CSV.
- `data/metadata/d3s_inventory.csv` contains the video identifier, relative
  path, filename, subject and class fields, label provenance, resolution,
  dimensions, FPS, frame count, duration, and file size.
- `scripts/create_dataset_exploration_notebook.py` creates the reproducible,
  executed notebook from the CSV without embedding machine-specific paths.
- `notebooks/01_dataset_exploration.ipynb` contains inventory inspection,
  class-frequency, duration, and subject-balance visualizations, metadata
  provenance notes, and leakage-safe split guidance.
- `tests/unit/T0202_260929_2131_test_d3s_inventory.py` validates the exact CSV
  schema, non-empty records, positive video measurements, resolution
  consistency, cache exclusion, and structured path parsing.

## 4. Guardrail Validation

- **Path resolution:** scripts derive the repository root from `__file__` with
  `pathlib.Path`; no absolute machine paths are stored in generated artifacts.
- **Raw-data integrity:** inventory generation opens source videos read-only
  and writes derived metadata beneath `data/metadata/`.
- **Git protection:** both the source MP4 and its `_downloads` copy match the
  repository's `*.mp4` ignore rule. No files were staged during T0202 work.
- **Label integrity:** missing subject and class metadata remains `UNKNOWN`;
  no visual guess or unsupported label is treated as ground truth.
- **Leakage prevention:** the notebook prohibits random frame splits and
  requires subject-level separation where possible, otherwise complete
  video/session-level separation.
- **Resource cleanup:** every OpenCV capture is released in a `finally` block.
- **Traceability:** the unit test follows the mandated T0202 timestamped naming
  convention.

## 6. Limitations and Follow-up

The available MP4 does not expose reliable subject, session, or behavior
boundaries in its filesystem metadata. Before model evaluation or dataset
splitting, the team must obtain the structured D3S release or create a reviewed
segment annotation file that records subject, label, source video, and temporal
boundaries. After that metadata is available, regenerate the inventory and
rerun the notebook so the four class distributions and three subject balances
represent verified observations.

Until then, the monolithic source video must remain entirely within one data
partition. Its frames must not be randomly distributed across training,
validation, and test sets.
