## 1. Executive Summary

Task T0301 implemented deterministic video-file and live-camera acquisition
interfaces for the Driver Drowsiness Detection System. Both interfaces emit the
required `(frame_id, timestamp, raw_frame)` tuple with the concrete types
`(int, float, numpy.ndarray)`. The package remains limited to input lifecycle
and raw BGR frame delivery; it contains no face detection, feature extraction,
temporal analysis, or drowsiness decision logic.

`VideoReader` resolves repository-relative paths, validates video availability,
extracts technical metadata, calculates frame-relative timestamps, detects end
of stream, and releases its OpenCV capture. `CameraStream` supports optional
capture dimensions, creates monotonic elapsed timestamps with
`time.perf_counter()`, stops cleanly when frame reads fail, and releases its
camera resource.

## 3. Functional Implementation

### 3.1 VideoReader

- Accepts a `str` or `pathlib.Path` and resolves relative input against the
  repository root.
- Raises `FileNotFoundError` with the resolved path when the file is absent.
- Raises `ValueError` when OpenCV cannot open the file or reports non-positive
  FPS metadata.
- Reads OpenCV properties once during initialization and computes duration as
  `total_frames / fps` when a positive frame count is available.
- Yields zero-based frame IDs and timestamps calculated as `frame_id / fps`.
- Treats a failed read, `None`, or an empty array as end of stream.
- Releases the capture after normal EOF, generator interruption, or context
  manager exit.

### 3.2 CameraStream

- Opens an integer camera device ID and optionally requests capture width and
  height through OpenCV properties.
- Raises an actionable `ValueError` when the requested device is unavailable.
- Yields zero-based frame IDs and elapsed monotonic timestamps derived from
  `time.perf_counter()`.
- Stops on a failed, missing, or empty frame, including camera disconnection.
- Releases the capture from the iterator's `finally` block and on context
  manager exit.

## 4. Contract and Guardrail Validation

- **Pipeline schema:** both readers return exactly
  `(int, float, numpy.ndarray)` and preserve raw OpenCV BGR frames.
- **Module boundary:** `src/acquisition/` imports no MediaPipe, facial-landmark,
  EAR, MAR, temporal, alert, or classification code.
- **Path portability:** video paths use `pathlib.Path`; no machine-specific
  absolute path is embedded in source or tests.
- **Clean failure:** missing files, invalid FPS, unavailable cameras, and
  iteration after release produce explicit exceptions or clean stream endings.
- **Graceful exit:** OpenCV captures are released after EOF, interruption,
  disconnection, or context-manager exit. These modules do not create GUI
  windows, so `cv2.destroyAllWindows()` is not applicable at this layer.
- **Traceability:** the test and this report follow the mandatory
  T0301 timestamped naming convention.

## 7. Limitations and Follow-up

- Camera behavior is unit-tested with a deterministic capture mock because CI
  environments cannot assume physical webcam access. A manual smoke test should
  be performed on the demonstration machine before the live demo.
- Video timestamps use `frame_id / fps`, which is deterministic and appropriate
  for constant-frame-rate input. If variable-frame-rate footage becomes a
  verified project requirement, evaluate `CAP_PROP_POS_MSEC` behavior against
  representative files before changing the timestamp policy.
- OpenCV metadata quality depends on the source container and codec. Invalid FPS
  is rejected rather than allowing misleading timestamps, while unavailable
  frame counts produce a duration of `0.0`.

T0301 is complete and ready to provide raw frames to the downstream detection
stage without expanding the acquisition package beyond its assigned boundary.
